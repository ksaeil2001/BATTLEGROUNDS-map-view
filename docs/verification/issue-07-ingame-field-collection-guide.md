## 1. 궁전(`Palace`) vs 터미널(`Terminal`) `Target Zone` 선정 비교 기준

두 후보 구역 중 **`31.2` 지도 이미지(`pubg/api-assets` `Taego_Main_High_Res.png`)와 현재 라이브 게임 내 지형·지붕 배치가 100% 일치하는 구역 1곳**만 최종 `Target Zone`으로 확정한다.

| 평가 항목 | 우선순위 | 궁전 (`Palace`) 확인 포인트 | 터미널 (`Terminal`) 확인 포인트 | 통과/선정 기준 |
| :--- | :---: | :--- | :--- | :--- |
| **1. `31.2` 지도 이미지 vs 현재 라이브 인게임 지붕 일치율** | **필수 게이트 (1순위)** | • 구역 외곽 담장·정전·행랑·별채 개수 및 지붕 방향 일치 여부<br>• 최근 패치(예: `38.x`~`42.x`)에서 가건물 추가·철거 여부 | • 본관 대합실·활주로/주차장 부속 창고·화물 건물 개수 및 지붕 윤곽 일치 여부<br>• 구조물 개편·엄폐물 변경 여부 | **불일치 0건(100% 일치)인 구역만 합격.** 한쪽만 일치하면 해당 구역 자동 확정 |
| **2. 지붕 다각형 기하학 다양성** | 2순위 | ㄱ자·ㄷ자 행랑 등 오목 다각형과 사각형 건물이 고르게 분포하는가? | 대형 본관, 직사각 창고, 좁은 부속동이 인접해 있는가? | `Pilot Slice` 3개로 오목 다각형 히트 판정·인접 분리를 시험하기 유리한 구역 우대 |

## 2. 공식 `31.2` 지도 이미지와 인게임 지붕 배치 대조 방법

1. **기준 지도 준비 (로컬 전용, Git 커밋 금지)**:
   - `pubg/api-assets`의 `Assets/Maps/Taego_Main_High_Res.png` (커밋 `32b13b5`, `Map Image Version: "31.2"`, `8192 × 8192`)에서 `Palace` 또는 `Terminal` 영역을 로컬 PC에만 열어 둔다.
   - 권리 확인(Issue #8) 전까지는 절대 `public/` 등 공개 배포 디렉터리나 Git 저장소에 커밋하지 않는다.
2. **인게임 리플레이 수직 탑뷰(Top-Down) 촬영**:
   - 태이고 일반 매치 또는 사용자 지정 매치에서 두 구역 상공을 통과하거나 구역 내부를 충분히 탐색한 뒤 **리플레이(Replay)** 를 연다.
   - 자유 시점(`Free Camera`)을 구역 정중앙 상공 약 `150m ~ 250m`로 이동한다.
   - 카메라 피치를 수직 아래(`-90°`)로 내리고, 미니맵의 북쪽(`N`)이 화면 상단(12시 방향)과 평행하도록 회전 정렬한다.
   - `Ctrl + U`로 HUD를 숨긴 뒤 탑뷰 스크린샷을 촬영한다.
3. **5단계 육안 대조 체크**:
   - [ ] 외곽 도로·담장·주차장 선형 기준 축척 및 회전 일치 확인
   - [ ] 전체 건물 동 수 일치 확인 (신규 추가·철거된 건물 유무)
   - [ ] 각 건물의 ㄱ자/ㄷ자/일자 지붕 꺾임 방향 및 별채 연결 여부 일치 확인
   - [ ] 중정·마당 안쪽의 작은 정자/창고/엄폐 지붕 존재 여부 확인
   - [ ] 차고 건물 위치(차고 지붕 및 개폐 문 방향) 일치 확인

## 3. `Pilot Slice` 인접 건물 3개 외관·층수·옥상·출입구 촬영 체크리스트

확정된 `Target Zone`에서 **서로 지붕이 가깝게 맞닿아 있는 인접 건물 3개(`isPilotSlice: true`)** 를 우선 선정한다. (가급적 ㄱ자 등 오목 다각형 1개 이상 포함 권장)

### 건물별 현장 조사 체크리스트 (`buildingId` 1건당 1세트 작성)

- **식별 메타**:
  - `id`: `<zoneId>-01`, `<zoneId>-02`, `<zoneId>-03` (예: `palace-01`)
  - `buildingType`: 현장에서 식별되는 직관적 건물 명칭 (예: `"서측 ㄱ자 행랑"`, `"2층 발코니 상가"`)
- **체크 1 — 외관 사진 (`attributes.exteriorImage`)**:
  - [ ] 주간·맑음 등 식별이 잘 되는 밝은 시간대/날씨 리플레이에서 촬영
  - [ ] 지붕 윤곽·전체 층수·주 출입구가 대각선 또는 정면 구도로 한 화면에 들어오게 촬영
  - [ ] `Ctrl + U`로 HUD/플레이어 이름/킬로그 완전 제거 (타 플레이어 닉네임 노출 금지)
  - [ ] 촬영 본인의 패치 버전(`capturedPatch`, 예: `"42.2"`) 기록
- **체크 2 — 층수 (`attributes.floors`)**:
  - [ ] 실제로 플레이어가 문을 열고 계단 등으로 들어가 이동할 수 있는 층 수만 계수 (`1`, `2`, `3` 등 정수)
  - [ ] 장식용 다락/미개방 옥탑은 층수에 포함하지 않고 비고에만 구분 기록
  - [ ] 직접 들어가보지 않은 경우 절대 추정 금지 → `status: "unverified"`
- **체크 3 — 옥상 접근 방식 (`attributes.rooftopAccess`)**:
  - [ ] **`interior-stairs`**: 건물 내부 계단을 걸어 올라가 옥상 바닥/문으로 직접 나갈 수 있음을 직접 확인함 (어느 쪽 계단인지 1문장 요약 작성)
  - [ ] **`exterior-climb`**: 내부 계단은 없으나, 외부 난간·박스·에어컨 실외기·차량·인접 지붕 파쿠르(`Space`) 또는 고정 사다리로 지붕에 올라갈 수 있음을 직접 실험해 성공함 (진입 지점/방법 1문장 요약 작성)
  - [ ] **`inaccessible`**: 내부 옥상 계단이 없고 외부 지형·구조물 파쿠르로도 지붕 등반이 불가능함을 **충분히 시험하여 확인한 경우에만** 선택
  - [ ] **아직 테스트하지 못함**: 절대 `inaccessible`로 표기하지 말고 `status: "unverified"` (`note: "외부 파쿠르 루트 미확인"`)로 남김 (`ADR-0002` 필수 규칙)
- **체크 4 — 출입구 수 및 방향 (`attributes.entrances`)**:
  - [ ] 1층 외부 땅에서 건물 내부로 걸어서 드나들 수 있는 문/열린 아치의 총 개수(`count`) 직접 확인 (건물 한 바퀴를 360° 돌며 전 방향 점검)
  - [ ] 각 문의 나침반 방위(`북/남/동/서` 기준) 및 구분 기록 (`directionsSummary`, 예: `"남쪽 정문 1, 동쪽 측면문 1, 서쪽 후문 1"`)
  - [ ] 창문(파쿠르 진입만 가능한 창)은 출입구 `count`에서 제외

> **`Pilot Slice` 통과 후 확장(약 20개 건물)**: 동일한 체크리스트를 `Target Zone` 내 나머지 주요 건물(~17개)에 순차 적용하며, 아직 외관 사진이나 옥상 테스트를 완료하지 못한 건물은 확인된 속성만 `verified`로 두고 나머지는 `unverified` 상태로 등록 가능하다.

## 4. `Fixed Vehicle Spawn Point`의 게임 모드·차종·좌표 검증 방법

1. **고정 스폰과 일반 랜덤 스폰의 엄격한 분리**:
   - 일반 도로변에 확률적으로 생성되는 랜덤 스폰은 제외하고, **차고지(`garage`)** 또는 패치노트·공식 안내·다수 매치 리플레이에서 동일 지점 반복 생성이 교차 확인된 **지정 고정 스팟(`fixed-spot`)** 만 수집한다.
   - `Fixed Vehicle Spawn Point`라도 매 경기 100% 출현을 보장하지 않으므로, **"매 경기 100% 확정"** 이나 미검증 **출현 확률(%)** 문구는 절대 수집/기록하지 않는다.
2. **필수 검증 항목 (`src/domain/types.ts` `FixedVehicleSpawnRecord` 기준)**:
   - `id`: `<zoneId>-vehicle-01` 또는 구역 인접 광역 도로인 경우 `taego-wide-vehicle-01`
   - `zoneId`: 구역 내부·바로 인접이면 `<zoneId>`, 태이고 전역 간선도로 확장분이면 `"taego-wide"`
   - `gameMode`:
     - `"normal"`: 일반 매치(노멀)에서 확인됨
     - `"ranked"`: 경쟁전(랭크)에서 확인됨
     - `"esports"`: 이스포츠 스폰 규칙으로 확인됨
     - `"all-verified"`: 일반·경쟁전 등 적용 대상 모드 모두에서 동일 위치 확인됨
     - *주의*: 일반 매치 차고 위치가 경쟁전/이스포츠에서 고정/비고정 여부가 다를 수 있으므로 실제 확인한 모드 값만 정확히 기록한다.
   - `spawnType`: `"garage"` (차고 내부) | `"fixed-spot"` (야외 지정 고정 위치)
   - `vehicleTypes`: 해당 위치에서 실제 출현을 확인한 차종 목록 (예: `["포니 쿠페"]`, `["포터", "다시야"]`)
   - `verificationSource`: 독립적인 매치 리플레이 N회(최소 2회 이상 권장) 및/또는 공식 패치노트 번호를 구체적으로 명시 (예: `"패치 42.2 일반 매치 리플레이 3회 직접 확인"`)
   - `notes`: 모드별 특이사항 또는 *"고정 스폰 지점이나 매 경기 100% 확정 출현을 의미하지 않음"* 안내만 간결하게 기록

## 5. 증거 자료 파일명·패치 버전·검증 날짜 기록 형식

### 5.1 증거 자료 및 이미지 파일명 규칙

| 구분 | 저장 경로 규칙 (로컬 증거 보관 / 권리 확인 후 배포) | 예시 |
| :--- | :--- | :--- |
| **구역 탑뷰 대조본** (로컬 검수 전용) | `evidence/<zoneId>-topdown-patch-<verifiedGamePatch>-<YYYYMMDD>.webp` | `evidence/palace-topdown-patch-42.2-20261116.webp` |
| **건물 외관 사진** (권리 준수 가공본) | `public/buildings/<buildingId>-patch-<capturedPatch>.webp` | `public/buildings/palace-01-patch-42.2.webp` |
| **차량 스폰 증빙 스샷** (로컬 검수 전용) | `evidence/<vehicleId>-<gameMode>-patch-<verifiedGamePatch>-<YYYYMMDD>.webp` | `evidence/palace-vehicle-01-normal-patch-42.2-20261116.webp` |

- `public/buildings/` 이미지 권장 규격:
  - 포맷: **WebP** (권장 해상도 `800×500` 내외, `16:10` 또는 `16:9`, 파일당 `150KB` 이하 경량화)
  - 크롭 시 닉네임·채팅·미니맵·킬로그가 남지 않게 트리밍

### 5.2 JSON `Verification Record` 및 판본 표준 기록 형식

모든 건물 레코드(`src/data/buildings.json`)와 차량 레코드(`src/data/vehicles.json`)는 아래 스키마 규칙을 그대로 사용한다.

```json
{
  "mapImageVersion": "31.2",
  "provenance": {
    "verificationStatus": "verified",
    "verificationSource": "사용자 지정 매치 및 일반 매치 리플레이 3회 대조 확인",
    "verifiedGamePatch": "42.2",
    "verifiedAt": "2026-11-16"
  }
}
```

- **용어 분리 주의 (`GLOSSARY.md`)**:
  - `mapImageVersion`: 좌표를 찍은 **배경 지도 파일 판본** (예: `"31.2"`).
  - `verifiedGamePatch`: 인게임에 접속해 **실제 건물/차량을 눈으로 확인한 게임 패치 버전** (예: `"42.2"`).
  - `verifiedAt`: `YYYY-MM-DD` (ISO-8601 날짜 형식).
- **미확인 속성 기록 예시 (`ADR-0002` 준수)**:
  ```json
  "rooftopAccess": {
    "status": "unverified",
    "note": "외부 담장 파쿠르 가능 여부 미확인"
  },
  "exteriorImage": {
    "status": "unverified",
    "note": "정면 외관 스크린샷 촬영 대기"
  }
  ```

## 6. `DevCoordinatePicker`로 실제 좌표를 추출하고 검수하는 절차

구현된 개발 전용 도구 `DevCoordinatePicker`([DevCoordinatePicker.tsx](../../src/components/dev/DevCoordinatePicker.tsx))는 `NODE_ENV === 'development'`일 때만 활성화되며, 지도 클릭 좌표를 자동으로 `Canonical Pixel Space`(`0..8192`) 정수 `[x, y]`로 변환한다.

### Step 1. 개발 서버 실행 및 진입
1. 터미널에서 `npm.cmd run dev`를 실행한다.
2. 브라우저에서 `http://127.0.0.1:3000`에 접속한 뒤 **`태이고 (Taego)`** 맵 카드를 클릭한다.
3. *(로컬 정밀 대조 작업 시)* 공식 `31.2` 이미지를 사용할 때는 Git에 커밋되지 않는 임시 로컬 설정으로만 마운트하고, Issue #8 권리 확인 전에는 절대 원격 저장소에 푸시하지 않는다.

### Step 2. 좌표 추출기 활성화 및 일반 클릭 차단 확인
1. 우측 하단 개발 전용 패널의 **`좌표 추출기 OFF (DEV)`** 버튼을 클릭한다.
2. 버튼 문구가 **`좌표 추출기 ON (편집 중)`** 으로 바뀌고 모드 선택 버튼이 나타나는지 확인한다.
3. 이 상태에서는 등록된 건물 지붕이나 차량 마커를 클릭해도 `Building Card`나 차량 상세 카드가 열리지 않고 오직 좌표 추출만 동작한다.

### Step 3. 건물 `Roof Footprint` 다각형 좌표 추출
1. 모드 버튼 중 **`다각형 (Roof Footprint)`** 가 선택(활성)되었는지 확인한다.
2. 대상 건물 지붕이 선명하게 보이도록 마우스 휠로 최대한 확대한다.
3. 지붕 처마 외곽 모서리를 **시계 방향(또는 반시계 방향) 한 방향 순서대로** 클릭해 꼭짓점을 찍는다.
   - 직사각형 건물: 4개 꼭짓점
   - ㄱ자·ㄷ자 오목 건물: 안쪽 꺾임 모서리를 빠짐없이 포함한 6~8개 꼭짓점
   - *참고*: 닫힌 다각형을 만들기 위해 마지막 점에 첫 점을 한 번 더 찍을 필요는 없다 (`isPointInPolygon`이 마지막 점과 첫 점을 자동 연결함).
4. **오입력 교정**:
   - 직전 1개 점만 잘못 찍은 경우: **`점 되돌리기 (Undo)`** 클릭
   - 처음부터 다시 찍을 경우: **`취소 (Cancel)`** 클릭
5. 하늘색(`#38bdf8`) 점선 미리보기 다각형과 번호가 매겨진 꼭짓점이 실제 지붕 외곽과 1px 오차 없이 맞는지 눈으로 확인한다.
6. **`JSON 복사 (Copy JSON)`** 버튼을 클릭해 `[[x1,y1],[x2,y2],...]` 문자열을 클립보드에 복사하고 (`복사 완료` 표시 확인), 건물 레코드의 `footprint` 필드에 붙여넣는다.

### Step 4. `Fixed Vehicle Spawn Point` 단일 좌표 추출
1. 모드 버튼 중 **`고정 차량 출현 지점 (Single Point)`** 버튼을 클릭한다.
2. 차고 건물 입구 중앙 또는 확인된 야외 고정 스팟 정중앙을 클릭한다. (다른 지점을 다시 클릭하면 기존 점 1개가 새 점으로 자동 교체됨)
3. **`JSON 복사 (Copy JSON)`** 버튼을 클릭해 `[x,y]` 단일 정수 좌표를 복사하고, 차량 레코드의 `coord` 필드에 붙여넣는다.

### Step 5. 추출 좌표 브라우저·자동 테스트 검수
1. **`좌표 추출기 ON (편집 중)`** 버튼을 다시 눌러 **`좌표 추출기 OFF (DEV)`** 로 종료한다.
2. 브라우저에서 5가지 수동 QA를 수행한다:
   - [ ] 등록한 건물 지붕 **정중앙 및 안쪽 모서리** 클릭 시 해당 건물의 `Building Card`만 정확히 열리는가?
   - [ ] ㄱ자 건물의 **오목 바깥 여백**·인접 도로·인접 건물 사이 틈새 클릭 시 어떤 카드도 열리지 않고 기존 카드가 닫히는가?
   - [ ] 인접한 `Pilot Slice` 3개 건물을 차례로 클릭했을 때 각각 자기 자신의 카드(`palace-01`, `02`, `03` 등)로 정확히 전환되는가?
   - [ ] 줌 인/아웃 및 모바일 뷰포트(`390×844`)로 창 크기를 바꾼 뒤에도 윤곽선·차량 마커가 지붕/도로 위치에서 1px 이상 밀리지 않는가?
   - [ ] `차량 위치 ON/OFF` 토글이 켜졌을 때 차량 마커 클릭 시 건물 선택과 충돌 없이 `VehicleSpawnCard`가 열리는가?
3. 터미널에서 스키마·좌표·히트 테스트·E2E 정합성을 검증한다:
   - `npm.cmd run typecheck` (TypeScript 0 errors 확인)
   - `npm.cmd run test` (Vitest 도메인/좌표 테스트 통과 확인)
   - `npm.cmd run test:e2e` (Playwright PC·모바일 테스트 통과 확인)
