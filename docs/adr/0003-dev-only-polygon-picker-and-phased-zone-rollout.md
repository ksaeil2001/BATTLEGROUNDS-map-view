# 0003. Dev-Only Polygon Picker and Phased Zone Rollout

- Status: accepted

## Context

건물 지붕 다각형(`Roof Footprint`)과 고정 차량 좌표를 외부 이미지 편집기에서 수동 측정해 JSON에 입력하면 오차가 생기기 쉽고 인접 건물 간 경계 수정 비용이 크다. 동시에 좌표 편집 도구가 프로덕션 배포 빌드에 노출되면 일반 사용자의 지도 탐색 경험과 번들 경량화를 해친다. 또한 20개 건물을 한 번에 등록한 뒤 좌표·클릭 오작동을 발견하면 재작업 범위가 커진다.

## Decision

1. **개발 환경 전용 Polygon & Coordinate Picker**: `process.env.NODE_ENV === 'development'` 환경에서만 활성화되는 내장 좌표 추출 도구를 구현한다. 프로덕션 빌드 및 배포 환경에서는 접근할 수 없도록 라우팅과 번들에서 제외한다.
2. **편집 기능 및 이벤트 격리**: Picker는 `Canonical Pixel Space`(`8192 × 8192`) 기준 꼭짓점 추가, 마지막 점 되돌리기(Undo), 선택/편집 취소, JSON 복사 기능을 제공하며, 편집 모드 활성 중에는 일반 건물 카드 오픈·선택 이벤트가 발생하지 않도록 차단한다.
3. **단계적 구역 검증 롤아웃**:
   - **1단계 (`Target Zone` 선정)**: 궁전(`Palace`)과 터미널(`Terminal`) 중 현재 인게임 건물 배치와 31.2 지도 이미지가 정확히 일치하는 1개 구역을 확정한다.
   - **2단계 (`Pilot Slice` 3개 검증)**: 인접한 건물 3개 지붕 윤곽을 먼저 등록해 다각형 클릭 정확도, 인접 건물 분리, 모바일 터치 가드를 검증한다.
   - **3단계 (구역 확장)**: 검증을 통과한 뒤 해당 `Target Zone` 내 약 20개 건물과 구역·인접 도로의 확인된 `Fixed Vehicle Spawn Point`로 확대하고, 이후 태이고 전역 차량 스폰으로 확장 가능한 구조를 유지한다.

## Considered Options

- QGIS 등 외부 GIS 툴이나 포토샵으로 픽셀 좌표를 수동 측정해 JSON을 작성하는 방식 (반복 수정 및 인접 건물 겹침 검증 속도가 떨어져 기각)
- 런타임 쿼리 파라미터(`?dev=true`)만으로 숨기는 방식 (배포 환경에서도 코드가 번들링되어 접근 가능하므로 프로덕션 차단 원칙에 어긋나 기각)

## Consequences

- 실제 렌더링되는 Leaflet `CRS.Simple` 좌표계 위에서 직접 지붕 윤곽을 찍고 즉시 클릭 테스트를 수행하므로 좌표 오차와 재작업 비용이 크게 줄어든다.
- 배포 환경에서 편집 UI·핸들러가 완전히 제거되어 일반 사용자는 지도 탐색·건물 클릭·차량 레이어 토글에만 집중할 수 있다.
