# 0001. Canonical Pixel Space and Hybrid Map Overlays

- Status: accepted

## Context

`pubg/api-assets`의 태이고 고해상도 지도 원본 PNG(`8192 × 8192`)는 용량이 101MB에 달해 초기 화면에서 그대로 로드하면 네트워크 지연 및 모바일 메모리 초과를 유발할 수 있다. 반면 저해상도 프리뷰 이미지(약 1.31MB)만 사용하면 지붕 윤곽을 정밀하게 식별·클릭하기 어렵고, 향후 지도 이미지 해상도를 교체하거나 정적 타일로 전환할 때 기존 건물·차량 좌표가 어긋나는 문제가 발생한다. 또한 태이고 공식 지도 이미지의 상업·재배포 권한 확인 전까지는 공개 배포 자산과 개발 검증 자산을 안전하게 분리할 수 있어야 한다.

## Decision

1. **기준 픽셀 좌표계(`Canonical Pixel Space`) 고정**: 모든 건물 `Roof Footprint` 다각형과 `Fixed Vehicle Spawn Point` 좌표는 배경 이미지 해상도와 무관하게 원본 좌상단 `(0, 0)` 기준 `8192 × 8192` 평면 좌표로 저장하며, Leaflet `CRS.Simple`에서 `[8192 - y, x]`로 단일 변환해 사용한다.
2. **2단계 하이브리드 지도 표시(초기 단순 구현 → 측정 후 타일 검토)**: 초기 버전은 서버·타일 파이프라인 없이 경량 WebP 전체 지도를 기본 배경으로 두고, `Target Zone`에만 `8192 × 8192` 기준 고해상도 크롭 WebP 오버레이를 정확한 바운딩 박스에 중첩한다. 정적 타일 피라미드(`L.tileLayer`) 도입은 실제 기기 성능 측정 결과 병목이 확인된 이후로 미룬다.
3. **판본 대조 및 공개 배포 권리 게이트**: 실제 구역 좌표 등록 전 31.2 지도 이미지와 현재 라이브 게임의 지형·지붕 배치 일치를 먼저 확인하며, 지도 이미지의 사용 권한이 확인되기 전에는 공식 게임 이미지를 공개 배포하지 않고 필요 시 자체 제작 샘플 지도로 대체한다.

## Considered Options

- 초기부터 `8192 × 8192` 전체 이미지를 다단계 정적 타일 피라미드로 분할해 `L.tileLayer`로 서빙하는 방식 (초기 구현·빌드 파이프라인 복잡도 증가로 보류)
- 101MB 원본 PNG를 단일 `L.imageOverlay`로 직접 로드하는 방식 (초기 로딩 및 모바일 메모리 문제로 기각)

## Consequences

- 배경 이미지 해상도를 변경하거나 추후 정적 타일 방식으로 전환하더라도 `buildings.json` 및 `vehicles.json`의 좌표를 재계산할 필요가 없다.
- 지도 이미지 파일(`mapImageVersion`)과 인게임 검증 패치(`verifiedGamePatch`)가 분리 관리되므로, 부분 패치 시 구역 단위 고해상도 오버레이만 독립적으로 교체할 수 있다.
